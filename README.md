# Какой ты студент РГГУ?

Telegram Mini App с тестом из 15 вопросов: пользователь выбирает варианты ответа, а приложение
считает баллы по шести студенческим типам и показывает результат. Результат можно сохранить
PNG-карточкой или отправить через системное меню «Поделиться».

Все экраны перенесены из макета Figma: обложка, «Как это работает», 15 вопросов, экран
подсчёта, 6 экранов результата и экран карточки.

## Стек

- Vanilla HTML / CSS / JS, без сборки, зависимостей и фреймворков.
- Только статические файлы: проект можно открыть с любого HTTPS-хостинга.
- Шрифты лежат локально в `assets/fonts` (Inter, Nunito, Caveat, Baloo 2), интернет для них не нужен.
- Карточка результата рисуется в `<canvas>` в 3× (918 × 1416 px) и отдаётся как PNG.

## Локальный запуск

Открывать файл напрямую через `file://` не стоит: браузер ограничит загрузку шрифтов и
`canvas.toBlob`. Запустите любой статический сервер из корня проекта:

```bash
python3 -m http.server 4173
```

и откройте <http://127.0.0.1:4173>. Подойдёт и `npx serve .`, и «Live Server» в VS Code.

## Публикация

Telegram Mini App должен открываться по **HTTPS**. Подойдёт любой статический хостинг.

### Vercel

```bash
npm i -g vercel
vercel
```

Либо импортируйте репозиторий на <https://vercel.com/new>: framework — «Other», build command
и output directory оставьте пустыми.

### Netlify

Перетащите папку проекта в <https://app.netlify.com/drop> или выполните:

```bash
npx netlify-cli deploy --prod --dir .
```

### GitHub Pages

1. Запушьте проект в репозиторий.
2. Settings → Pages → Source: `Deploy from a branch`, ветка `main`, папка `/ (root)`.
3. Приложение будет доступно по адресу `https://<username>.github.io/<repo>/`.

Папку с `.fig` и служебные файлы при желании исключите из деплоя — приложению нужны только
`index.html`, `styles.css`, `js/` и `assets/`.

### Проверка до публикации

- Откройте адрес на телефоне: не должно быть горизонтального скролла, текст не обрезается.
- Проверьте «Скачать карточку»: на iOS/Android должна открыться системная шторка «Поделиться»,
  а если Web Share API недоступен — карточка скачается файлом.

## Подключение к Telegram

1. Откройте [@BotFather](https://t.me/BotFather) и создайте бота: `/newbot`.
2. Создайте Mini App: `/newapp`. BotFather попросит:
   - выбрать бота;
   - название (например, «Какой ты студент РГГУ?»);
   - описание;
   - иконку 640 × 360 и (опционально) GIF;
   - **Web App URL** — HTTPS-адрес из предыдущего шага;
   - short name (латинские буквы, например `rggu-test`).
3. Кнопка в меню чата: `/mybots` → выберите бота → **Bot Settings** → **Menu Button** →
   **Configure menu button** → укажите тот же URL и подпись, например «Пройти тест».
   После этого кнопка появится слева от поля ввода у всех пользователей.
4. Откройте Mini App: `https://t.me/<bot_username>/<short_name>` или через кнопку меню.

### Локальная отладка внутри Telegram

Пока нет HTTPS-хостинга, поднимите туннель к локальному серверу:

```bash
# вариант 1
npx localtunnel --port 4173

# вариант 2
cloudflared tunnel --url http://127.0.0.1:4173

# вариант 3 (нужен аккаунт)
ngrok http 4173
```

Полученный `https://…` адрес укажите в BotFather как Web App URL (или в Menu Button) и
переоткройте Mini App. После каждого изменения файлов достаточно обновить Mini App.

## Что уже интегрировано с Telegram

- `ready()`, `expand()`, `setHeaderColor('#fffcf7')`, `setBackgroundColor('#fffcf7')`.
- `disableVerticalSwipes()` — свайп вниз не закрывает Mini App во время прохождения.
- Нативная кнопка «Назад» (`BackButton`): скрыта на обложке, на остальных экранах повторяет
  внутреннюю навигацию. Дублируется кнопкой «←» в интерфейсе.
- `HapticFeedback`: лёгкий отклик на выбор ответа и переходы, `notificationOccurred('success')`
  на экране результата.
- «Поделиться» использует `navigator.share` с файлом PNG; если файлы не поддерживаются —
  скачивает карточку. Ошибка пользователя (закрыл шторку) не считается сбоем.
- Если приложение открыто вне Telegram, всё работает как обычный сайт: Telegram-вызовы
  пропускаются, навигация остаётся доступной.

## Как менять контент

### Вопросы и ответы

Всё лежит в `js/data.js`:

```js
{
  n: 1,
  title: "Текст вопроса",
  answers: [
    { letter: "A", text: "Текст варианта", image: 'assets/img/answers/q01a.webp',
      types: ["creator", "strategist"] },
    // B, C, D
  ]
}
```

- `letter` — буква A–D, она же подпись на карточке ответа;
- `text` — текст варианта;
- `image` — картинка 276 × 152 (webp), соотношение 1.8:1;
- `types` — один или два типа, которым начисляется по +1 баллу.

Картинки удобно заменить файлами с теми же именами в `assets/img/answers/`.

### Типы, описания и суперсила

В `js/data.js`, объект `types`:

- `name` — название с эмодзи (эмодзи не рисуется на PNG-карточке, но остаётся на экране);
- `desc` — описание на экране результата;
- `superpower` — текст на экране результата (обращение «ты»);
- `cardSuperpower` — текст для карточки (первое лицо, «Создаю…»). Если поле не задано,
  используется `superpower`;
- `image` / `imageCard` — картинки для экрана результата и карточки;
- `imgW`, `imgH`, `cardImgW`, `cardImgH` — размеры, с которыми картинка выводится
  (важно сохранить пропорции исходников).

### Приоритет при равенстве баллов

Массив `priority` в начале `js/data.js`. Если у нескольких типов одинаковый максимум,
побеждает тип, который стоит в массиве раньше:

```js
priority: ['explorer', 'creator', 'communicator', 'strategist', 'adventurer', 'chiller']
```

### Тексты интерфейса

Обложка, «Как это работает», подписи кнопок и заголовок карточки — в `js/app.js`
(функции `renderCover`, `renderHow`, `renderResult`, `renderCard`).

## Шрифты

В макете заголовки набраны **Baloo 2**, но у этого шрифта нет кириллицы. Поэтому:

- Baloo 2 700 подключён только для латиницы (например, символ `✧`);
- для кириллических заголовков используется **Nunito 700/800** как ближайшая замена;
- рукописные заголовки обложки — **Caveat 700**;
- основной текст — **Inter 400–700**.

Все шрифты локальные, `@font-face` — в `assets/fonts/fonts.css`. Если меняете шрифт, обновите
`--font-display` / `--font-hand` / `--font-ui` в начале `styles.css` и список файлов в
`fonts.css`. Для canvas-карточки шрифт должен быть предварительно загружен — это делает
`loadFonts()` в `js/card.js`.

## Карточка результата

`js/card.js` рисует PNG размером 306 × 472 при масштабе 3 (итог 918 × 1416). Метрики повторяют
фрейм «Карточка …» из макета. Если меняете размеры или тексты, проверьте:

- перенос текста суперсилы — 2 строки по 204 px, лишнее обрезается многоточием;
- длинное название типа автоматически уменьшается в `fitFont()` (24 → 17 px);
- изображение центрируется по ширине карточки.

Чтобы быстро проверить все шесть карточек, откройте консоль на странице и выполните:

```js
for (const t of Object.keys(TEST_DATA.types)) {
  buildCardBlob(t).then(b => {
    const a = document.createElement('a');
    a.href = URL.createObjectURL(b);
    a.download = t + '.png';
    a.click();
  });
}
```

## Поведение и ограничения

- Прогресс не сохраняется: каждый запуск начинается с обложки, ответы живут только в памяти.
- Один вопрос — один ответ; вернувшись назад, можно изменить выбор.
- Ответ даёт +1 каждому из двух указанных типов (двойной ответ).
- При равенстве баллов работает фиксированный `priority`.
- «Выйти» на экране карточки сбрасывает ответы и возвращает на обложку.
- Приложение рассчитано на мобильный экран 320–430 px; на планшете контент центрируется
  с максимальной шириной 430 px.
- Проверено в Chrome (headless, 390 × 844 @2x, а также короткие экраны 360 × 640 и 390 × 700):
  все экраны, 6 результатов, 6 PNG-карточек, навигация назад, disabled/enabled «Далее»,
  share и fallback-скачивание.
